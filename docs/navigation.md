# 导航职责与退出机制（0.5）

## 原版本的实际行为

0.4 的 `watch/NavigationEngine.kt` 调用 `AMapNavi.startGPS()`、`calculateWalkRoute()` / `calculateRideRoute()` 和 `startNavi()`，包括偏航重算在内的导航都运行在手表。手机只解析、发送起终点。原版本有长按菜单和通知“结束”操作，但导航主界面没有直接可见的结束按钮。

## 0.5 的职责

| 功能 | 执行设备 |
| --- | --- |
| 分享链接解析、起终点与出行方式选择 | 手机 |
| 高德 SDK、GPS 定位、步行/骑行算路、偏航重算、实时导航 | 手机 |
| 当前路段附近的最多 80 个路线点筛选 | 手机 |
| 箭头、距离、路名、路线绘制、转弯震动 | 手表 |
| 可选的手表屏幕朝向 | 手表，仅完整模式且处于交互前台时启用传感器 |

手机从用户可见界面启动定位前台服务，因此锁屏后可继续导航；不尝试通过后台的手表消息启动手机定位服务。这符合 Android 对[后台启动定位前台服务的限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。手表只运行 `dataSync` 前台服务，移除了定位权限、高德 SDK、Key 和独立运行标记。

## 开始与结束

手机点击“开始手机导航并打开手表”，授予手机精确定位权限并同意隐私说明后，启动手机导航。手表确认路线后开始接收指引。没有连接手表时不启动导航；同一手机会话绑定一个已连接手表节点。

手机首页、手表导航界面底部、手表首页及两端导航通知均可结束导航。手表返回操作提供“结束导航”“继续导航”和“返回后台”。返回后台会保留正在进行的导航，直接点击结束则停止整次会话。

手机结束时移除 SDK 回调，分别尝试停止导航、停止 GPS、销毁 SDK，清空任务并撤销前台通知；单个 SDK 清理调用失败不会跳过后续清理。手表结束时停止同步、震动、定时任务与消息监听，退出导航页并释放常亮和方向传感器。

手机到达目的地、初始化/算路失败也走同一结束流程。服务为 `START_NOT_STICKY`，不会自动复活已停止的导航。

## 通信与断连

- 使用 v2 路线协议，避免旧版手表收到路线后自行启用 GPS。必须同时升级两端。
- 手机通常每 3 秒发送指引，转弯提醒立即发送；手表每 10 秒发送会话心跳。实时指引通过 MessageClient 发送，不存入持久化 DataItem。
- 指引携带会话 UUID、递增序号和定位数据的年龄。手表拒绝其他会话、重复及乱序更新。设备开机时间不同不会导致过期判断失效。
- 手表主动结束先本地停止，再发即时停止消息及持久化停止 DataItem；手机结束发送即时终态及持久化终态。断开后重连时可补收停止信息，但旧数据不会自动开启导航。
- 手机首次等待手表确认约 90 秒；确认后无心跳约 60 秒即停止手机导航。手表约 30 秒无新指引即停止。检查随服务调度执行，系统休眠可能推迟检查。
- 超过 15 秒未更新的定位指引隐藏距离。默认省电模式不绘制路线或启用方向传感器；进入息屏也会停止方向传感器。

## 验证边界与实机验收

单元测试覆盖协议边界、跨设备时间基准、过期指引、会话隔离、乱序/重复包、终态后禁止恢复、断连超时。构建后应检查手表 APK 无高德 native 库或定位权限，手机 APK 包含 ARM64 库。

以下项目需要匹配签名、高德 Key 和配对真机完成，构建及单元测试不能替代这些检查：

1. 手机锁屏后，步行和骑行均持续收到真实指引，偏航后路线更新。
2. 分别从手表底部/首页/通知和手机首页/通知结束；确认手机定位停止、两端通知消失、手表无震动和常亮，随后可开始新路线。
3. 手机退出、强制停止或断开蓝牙/网络，验证超时及重连不恢复旧会话；停止后再开始新会话，旧停止包不影响新会话。
4. 验证到达、算路失败、拒绝定位权限、仅允许粗略位置及未在手表确认时均不会留下持续导航。
5. 在圆形手表检查结束按钮可见、返回选择、息屏切换和屏幕朝向；实际续航改善需同条件实测，不给出未测量的节电比例。
