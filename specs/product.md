# Kylins AmapNav 0.5

User-authorized independent implementation. New applicationId com.kylins.amapnav on phone/watch, independent UI/assets and MIT application source. No GPL application code or assets included. Proprietary AMap SDK is a separately declared dependency, not relicensed. Existing experiment remains available for rollback.

- Native ambient support + OngoingActivity keeps an active navigation task visible. Wrist wake remains controlled by system settings. Optional screen-on fallback affects active navigation only and clears on exit/stop. Never override user Home/Back actions with forced relaunches.
- Watch face-sized navigation: clock, large distance, turn glyph and next road, with a visible stop button during interactive use. Optional complete mode adds locally drawn real route geometry, remaining time/distance and eight-direction magnetic display-top heading. Ambient reduces luminance, shifts pixels and hides the interactive stop button. Default economical mode omits geometry/compass and reduces redraw frequency. Independent preview Activity is clearly labeled and cannot report navigation success.
- Phone foreground location service exclusively owns AMap SDK, GPS, walking/cycling planning, rerouting and navigation. Start from a visible phone Activity after privacy consent and fine-location permission. Watch contains no AMap dependency or location permission. Stale >15s hides distance; transmit age instead of cross-device elapsed-realtime timestamps. Phone computes a bounded 80-point local geometry window; watch only renders it and deduplicates turn vibration.
- Both devices have visible stop controls and notification actions. Watch Back offers end/continue/background. All stop/arrival/error paths release GPS/SDK, foreground services, listeners, pending callbacks, vibration, compass and screen-on state. Stop messages have a persisted DataItem fallback; route/session IDs and increasing frame sequences reject old updates. No START_STICKY resurrection. Phone stops after 90s without initial watch confirmation or 60s without subsequent heartbeats; watch stops after 30s without frames. Timeouts are checked by service handlers.
- Default watch display is economical. Complete display can draw local route geometry; compass is sampled only during interactive visible use and is stopped in ambient/background. Full or screen-on modes remain explicit user choices.
- Phone: receive ACTION_SEND text/plain; explicit paste/import button; parse known AMap URI parameter formats with GCJ-02 only. No automatic clipboard reads. HTTPS short links resolve only exact allowlisted AMap hosts, bounded redirects/size/time, no arbitrary-host fetch. Show parsed destination for user review before sending. Importing endpoints does not preserve an arbitrary selected route or via points; unsupported share forms give a clear error.
- Pair link uses same package/signature and narrow Wear DataLayer filters. Pending route expires after 10 minutes and cannot start after the session ended. Phone Send explicitly starts phone navigation and sends a v2 route; watch confirmation starts only the display relay. Both apps must be upgraded together; v1 route data cannot start the new relay or an old watch SDK. Persistent recent logs and export through document picker remain available.
- Explicit phone Send action requests remote WatchHome launch using official RemoteActivityHelper and a canonical random route-ID link. Link must match a pending paired-device route before notification start can invoke navigation. Handle route data arriving after the open request. Notification provides a real Start action. Single-task Home clears abandoned preview; launcher entry resumes active navigation without trapping Back actions.

Full live test requires new package-bound Key. Do not claim physical wrist-raise verification without the user wearing the watch.
