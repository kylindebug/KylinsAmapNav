# Kylins AmapNav 0.4

User-authorized independent implementation. New applicationId com.kylins.amapnav on phone/watch, independent UI/assets and MIT application source. No GPL application code or assets included. Proprietary AMap SDK is a separately declared dependency, not relicensed. Existing experiment remains available for rollback.

- Native ambient support + OngoingActivity keeps an active navigation task visible. Wrist wake remains controlled by system settings. Optional screen-on fallback affects active navigation only and clears on exit/stop. Never override user Home/Back actions with forced relaunches.
- Watch face-sized navigation: clock, large distance, turn glyph, next road, locally drawn real route geometry, remaining time/distance, eight-direction magnetic display-top heading. Default ambient retains full information with reduced luminance and pixel shift. Optional economical mode omits geometry/compass and reduces redraw frequency. Independent preview Activity is clearly labeled and cannot report navigation success.
- Foreground location service owns SDK; validate request, explicitly consent to SDK privacy, obtain fine location. Start GPS, wait for valid current fix, plan walk/ride, surface actual callbacks, stale >15s hides distance; dedupe vibration. Store bounded debug events without raw coordinates/key, sync with phone.
- Phone: receive ACTION_SEND text/plain; explicit paste/import button; parse known AMap URI parameter formats with GCJ-02 only. No automatic clipboard reads. HTTPS short links resolve only exact allowlisted AMap hosts, bounded redirects/size/time, no arbitrary-host fetch. Show parsed destination for user review before sending. Importing endpoints does not preserve an arbitrary selected route or via points; unsupported share forms give a clear error.
- Pair link uses same package/signature and narrow Wear DataLayer filters. Pending route expires after 10 minutes; no unsolicited navigation launch. Persistent recent logs, export through document picker, known China service queries.
- Explicit phone Send action requests remote WatchHome launch using official RemoteActivityHelper and a canonical random route-ID link. Link must match a pending paired-device route before notification start can invoke navigation. Handle route data arriving after the open request. Notification provides a real Start action. Single-task Home clears abandoned preview; launcher entry resumes active navigation without trapping Back actions.
- Verify malformed/hostile share inputs, coordinate order, staleness, route progress geometry, build/lint, device screenshots, paired send/receive, and inactivity/ambient behavior. Full live test requires new package-bound Key. Do not claim physical wrist-raise verification without the user wearing the watch.
